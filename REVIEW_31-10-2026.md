## 2. Major

### F1 · Major · VERIFIED — `ValueKind::Star` parameters have no accepted syntax: every `CMDSCOPE(...)` gets a bogus ERROR

All 33 star-kind parameters in the model are `CMDSCOPE` (ALTER/DEFINE/CLEAR/DELETE/
START/STOP/PING/RESET entries). `wants_group` (server/src/analysis.rs:1409-1411)
deliberately excludes `Star` from the pending-word mechanism, so the `( … )` group
that follows the parameter word has no owner and hits the "Unexpected group" error
(server/src/analysis.rs:1596-1604). The bare form fails too: the `wildcard` item
path (analysis.rs:1605-1622) rejects any `*` after the object name. IBM's railroad is
`CMDSCOPE( qmgr-name | * | ALL )` — i.e. the *only* real-world spellings all error.

```
$ printf 'ALTER QLOCAL(A) CMDSCOPE(*)\nALTER QLOCAL(B) CMDSCOPE(SYSTEM)\n' \
    | server/target/debug/examples/probe
error[4] Unexpected `( … )` group: no parameter stands before these values. …  (×2)
```

`CMDSCOPE(SYSTEM)` — an ordinary string value — is flagged as well, so it is the
group-owner plumbing, not the star value. Fix direction: treat Star like a normal
group-taking kind in `wants_group` (and let `check_values` accept `*` / names).

### F2 · Major · VERIFIED — z/OS `NAME=word` degrades to two words: valid z/OS commands get two false errors

`grammar.js:79` declares `seq(optional($._gap), $.word, '=', optional($._value_list))`,
but after `=` an *integer/string* value is forced into a `value` node while a **word**
value resolves as a plain command-level `word` item (LR conflict against the repeat
iteration; `optional(_value_list)` → ε). The `=` itself silently disappears — no
ERROR node, no diagnostic about it:

```
$ tree-sitter parse  # /tmp copy of the grammar, committed parser.c
DEFINE QALIAS(X) TARGET=NOPE
  → (command verb: DEFINE (word QALIAS) (argument …) (word TARGET) (word NOPE))
ALTER QLOCAL(A) MAXDEPTH=9
  → … (word MAXDEPTH) = (value (integer 9))      # this form works
```

Consequence in the server (release binary, `--check` or probe):

```
DEFINE QALIAS(X) TARGET=NOPE
error[4] 'NOPE' is not a parameter of DEFINE QALIAS — did you mean SCOPE?
error[5] Parameter TARGET was given without its value — write TARGET('some text'); …
```

Both false on valid z/OS console/CSQUTIL MQSC, and the `TARGET` reference to `NOPE`
loses hint 12 as well. The server explicitly supports the `=` form
(analysis.rs:1624-1660 "z/OS NAME=value"), so either the grammar must bind a word
after `=` to a `value` node (scanner/lexer precedence or an explicit hidden token),
or the `=`-form support is silently half-dead.

### M-1 · Major · VERIFIED — code 9 false positives from extractor `optional:false` artifacts (model pipeline)

`tools/extract_model.py:273-274` (`parse_dotted.add`) records a dotted-diagram
parameter printed without a `?`/`!` bracket as `optional:false`; when a command has
exactly one such parameter, analysis.rs:1696-1727 emits warning[9] "usually given
parameter X". Two of the three qualifying commands are plain valid MQSC:

```
DISPLAY SBSTATUS(*)   → warning[9] … usually given parameter SUBTYPE — expected something like SUBTYPE()
RESET CLUSTER(CL1)    → warning[9] … usually given parameter QMID   (QMID is z/OS-only)
```

(The empty `SUBTYPE()` example is a second-order blemish: `value_example()` renders
nothing for star/free kinds.)

### M-2 · Major · VERIFIED — extraction debris survives as `Enum` and rejects valid values (model pipeline)

`IFCID` (START/ALTER TRACE) is enum `['ifcid']`; `CLASS` (START/STOP/ALTER/DISPLAY
TRACE) is enum `['integer','integer:integer']` — page debris, not values:

```
START TRACE(2) IFCID(18)   → warning[5] Parameter IFCID accepts only these values: IFCID — `18` is not one of them.
START TRACE CLASS(BOGUS)   → warning[5] … accepts only these values: INTEGER:INTEGER …
```

`START TRACE(2) IFCID(18)` is the canonical spelling of that command. Neither param
is in the overlay's `flag_params`/repair families, and the pooled-enum guard
(`no_parameter_enumerates_its_own_siblings`) cannot see single-value debris.

### T1 · Major · VERIFIED — `lsp_smoke_test.py` negative diagnostic checks pass on zero publishes

tools/lsp_smoke_test.py:554-563 and 463-476: `diags2`/`diags4` start `[]` and the
assertions are "must not contain code X" — if the server published nothing (feature
fully broken, wrong URI, publish never awaited), the checks still pass. Every other
publish loop filters by URI and could have pinned "exactly N publishes" but doesn't.

### T2 · Major · VERIFIED — "a probe must never panic" is enforced nowhere

`server/examples/probe.rs` `.unwrap()`s stdin (can exit 101);
`tools/corpus_measure.py:41-42` ignores the producer's exit code;
`server/examples/complete.rs:49-70` prints `PANIC` at rc=0; no CI step runs `probe`
at all. AGENTS.md's stated contract ("`probe` must show no panics and stable
diagnostic counts") has no mechanical guard behind it.

## 3. Minor

### Server core

**F5 · Minor · VERIFIED — pending-parameter bookkeeping silently overwrites, losing the diagnostic it exists to give.**
analysis.rs:1413 (`pending = Some((up.clone(), *n))`) replaces a still-pending word
without flushing it. Repro (probe): `ALTER QLOCAL(A) DESCR REPLACE` → error[5]
"DESCR was given without its value" fires; but `ALTER QLOCAL(A) DESCR MAXDEPTH(9)`
→ **0 diagnostics** — the second known parameter (MAXDEPTH) eats the pending slot and
DESCR is never checked. Real runmqsc fails that second line too (it reads `MAXDEPTH`
as DESCR's bare value, then `(9)` is AMQ8405), so the silence is a false negative
even under the server's own parenthesized-values model.

**F6 · Minor · VERIFIED — tab check (code 8) flags tabs inside quoted strings and comment lines.**
analysis.rs:330-341 scans raw `text.lines()`, ignoring lexical context. `* ` column-0
comments and `DESCR('a<TAB>b')` are valid MQSC — inside quotes the tab is string data,
and the message's claim ("becomes part of a word and splits the command") is false
there. It already misfires on the shipped corpus: `dmpmqcfg/MC2P.mqsc:538` and
`MC3D.mqsc:291` are both tabs **inside quoted DESCR text** (confirmed with `cat -A`).

**F7 · Minor · VERIFIED (probe + code) — hint 12 can speak about a name that navigation refuses to know.**
The `Item::Val` branch calls `check_obj_ref` (analysis.rs:1639-1650), so
`DEFINE QALIAS(X) TARGET='NOPE'` gets hint[12] (probe confirms); but
`object_index` only registers sites for `Item::Arg` (analysis.rs:1167, `_ => {}` at
1204), so that same position has no definition/references/rename/hover site —
contradicting the AGENTS.md invariant that all name-resolution paths join through
`ObjectIndex::sites_in` "so they cannot disagree about what a name means".

**F8 · Minor · VERIFIED (code) — hover/hint wording says "open document" for closed, disk-scanned files.**
analysis.rs:2179 emits "…DEFINEd at line N of `…` **(another open document)**" and the
hint-12 message (analysis.rs:979) says "this script or **the other open documents**".
Both maps are fed from `index.definitions(...)`/`external_defs` (server.rs:67,101-103),
which since PR 7 includes **closed** workspace files — `workspace_index_smoke.py`
asserts hover/symbols work against closed files, so the parenthetical lies exactly
when the feature shines.
