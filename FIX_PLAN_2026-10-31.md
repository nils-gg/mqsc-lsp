# Fix plan — findings of REVIEW_31-10-2026.md

Planned at `main@18bda62` (v0.1.3 + 1). Covers every flagged issue:
F1–F11, M-1/M-2, m-1…m-12, N1–N6, G1/G2, V1–V3, C1–C5, R1, T1–T12.
Batches are ordered by risk and by the harness-truth-first principle: the
vacuous-test fixes (Batch 0) land **before** any behavior change, so every
later fix is guarded by gates that can actually fail.

## Ground rules (from AGENTS.md, binding on every batch)

- `model/mqsc-model.json` must stay **byte-identical to `extract_model.py` output** —
  semantic model changes go into the **overlay** (`model/mqsc-overlay.json`) or into
  the **extractor + a regeneration**, never by hand into the base JSON
  (`tools/check_model.py` guards it; IBM reference is local-only, so run it locally).
- Grammar changes only via `tree-sitter generate --abi 14`; prototype in a
  `/tmp/opencode` copy first; never a bare `generate` (it rewrites the committed
  `parser.c` to a newer ABI). `scanner.c` is hand-written and compiled directly by
  `build.rs` — C edits there need no regeneration.
- MSRV rustc 1.75: no `cargo update`, no touching the `=` pins.
- Gate set, run per batch:
  `cargo test`, `cargo fmt --check`, `cargo clippy -D warnings` (MSRV toolchain),
  `cargo build --release` → `python3 tools/lsp_smoke_test.py <release bin>` →
  `python3 tools/workspace_index_smoke.py <release bin>` →
  `server/target/release/mqsc-lsp --check dmpmqcfg/*.mqsc` diffed against the review
  baseline (rc=1, 19 940 findings: 19 882 hint[12], 21 warning[14], 19 error[1],
  15 error[4], 2 warning[8], 1 error[2]) → `check_model.py`, `check_versions.py`,
  `node tools/extension_resolve_test.js`, `node tools/extension_config_test.js` →
  `tree-sitter test` (grammar batches) → `tools/record_demo.sh` plain run
  (demo-staleness gate; several fixes touch hover/diagnostic text).
- Each behavioral fix = production change + a **new guard test that fails before the
  fix** + message-string updates (unit tests and both smokes pin exact text) in the
  same commit.

## Batch 2 — Grammar: z/OS `NAME=word` (F2, G1)

The riskiest change; isolated batch.

1. Prototype in a `/tmp/opencode/tsg` copy: after `=`, a **word** value must bind as
   a `value` node like integer/string already do. Approach: make the value list
   non-optional in the `=` rule (`seq(word, '=', $._value_list)`) plus a separate
   degenerate `NAME=` branch for `=` at item end (and/or `prec` to force the shift);
   keep `_gap`/comma/continuation tolerance intact.
2. `tree-sitter generate --abi 14` → `tree-sitter test` → parse-diff the whole
   `dmpmqcfg` corpus (expect *zero* shape change — the dumps are distributed form)
   → only then copy the generated `parser.c`/`grammar.json`/`node-types.json` back
   and commit.
3. Server-side follow-up: confirm `Item::Val` paths (`check_values`, `check_obj_ref`,
   the F7 sites, code-14 `when_vals`) actually fire on `NAME=word`.
   `DEFINE QALIAS(X) TARGET=NOPE` must now yield exactly hint[12] — no code 4/5.
4. **G1** lands with it: corpus cases pinning the repair/robustness contracts —
   unclosed group → MISSING `")"`, unterminated string ending at newline, stray `)`
   → ERROR, CRLF file, multibyte UTF-8 in strings/comments — plus `=`-form cases
   (word / integer / string / `*` values).
5. Re-run `server/tests/corpus.rs` (exact normalized-sexp is the real net), both
   smokes, corpus `--check` diff.

**Plan B (needs explicit sign-off, do not take silently):** if the LR conflict
cannot be resolved safely (continuations/`_gap` regress), deprecate the `=` form
instead — remove the half-dead `Item::Val` support and state in README that only
parenthesized values are supported.
